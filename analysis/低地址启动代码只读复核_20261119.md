# 低地址启动代码只读复核（2026-11-19）

本次只读取已有转储，没有连接相机、写入内存或触发升级。

## 已确认

- `lowmem_2M_64M.bin` 对应物理地址 `0x80200000–0x84200000`，不是 postboot 镜像的独立转储，而是 Linux 内核及用户态库的连续内存快照。
- 内核命令行字符串位于 `0x806abc1b`，包含 `mtdblock0`、`slram0=0x83100000,+0x00300000`、`slram1=0x83400000,+0x00A00000` 和 `console=ttyAMA,115200`。这与此前的 rootfs/program 固定加载地址一致。
- 内核注册了通用 AES 算法。可见 `aes-generic`（`0x8069a1f4`）、`crypto_aes_set_key`（`0x8061e7e6`）、`crypto_aes_expand_key`（`0x8061e7f9`）以及 OpenSSL `AES_set_encrypt_key`、`AES_decrypt` 等符号字符串。
- 同一快照还包含 `libcrypto.so.1.0.0` 和大量 Wi-Fi、TLS、WPA AES 字符串。现有证据只能说明 Linux 加密栈常驻，不能把这些符号绑定到机身固件分区解密流程。
- `lowmem_0_2M.bin` 与 `lowmem_after_official_v29.bin` 没有 `postboot`、`FW_UPDATE`、`NAND` 或 `AES` 明文标识。低地址常驻代码仍适合作为启动/异常入口研究对象，当前没有可直接命名的 postboot 入口。

## 研究结论

低地址转储补充了可定位的 Linux 加密 API 和启动命令行，但没有产生机身 AES 密钥、硬件 AES 寄存器映射或安全读写入口。后续软件路线应优先做异常向量、Reset 后跳转和内核加载地址的静态映射，避免把通用 Linux `aes-generic`/OpenSSL 误判为 Panasonic 更新解密实现。
