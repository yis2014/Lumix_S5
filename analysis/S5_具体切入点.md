# 原代 DC-S5：具体切入点与验证顺序

本轮继续只读研究，未连接相机、未刷写、未执行第三方程序。这里的“入口”区分为研究接口、已知明文验证点和代码执行入口；**目前没有得到代码执行或固件解密入口**，不能将下面的候选包装成已破解。

## 1. 优先：原代 S5 Wi-Fi 菜单/状态接口

### 实质发现

发现公开项目提供原代S5实机菜单资料，不必等到解密才能观察部分运行时设置：

- [原始 allmenu 来源](https://raw.githubusercontent.com/sapoepsilon/lumix-remote/985977636202bdeff5acaea82444c914834b1e1f/evidence/real-s5/s5_allmenu.xml)
- [原始 curmenu 来源](https://raw.githubusercontent.com/sapoepsilon/lumix-remote/985977636202bdeff5acaea82444c914834b1e1f/evidence/real-s5/s5_curmenu.xml)
- 已完整下载并解析：[本地 allmenu](remote_menu/s5_allmenu.xml)、[本地 curmenu](remote_menu/s5_curmenu.xml)、[提取结果](remote_menu/menu_findings.json)。

来源固定在提交985977636202bdeff5acaea82444c914834b1e1f。作者称原代DC-S5 fw2.03实机测试；这是外部提供的证据，不是我们自己对用户机身的测量。

XML自身包含 `menuset model="S5" version="2.0" date="20201027"`。这里version/date是菜单描述元数据，不能把它当作用户当前固件版本。

已获得具体标识：

- `menu_item_id_ph_sty_vlog`
- `title_ph_sty_vlog`
- `lvf_image_ctrl_v_log_sp`
- 命令描述：`cmd_mode=setsetting`, `cmd_type=photostyle`, `cmd_value=vlog`
- 当前菜单：`ph_sty_vlog enable=yes`，`ph_sty_vlog_l enable=no`
- `photostyle`还包含custom1..10、cinelike_d2/v2、709like等条目。

**价值：** 可比较用户机身在切换V-Log和监看LUT前后的菜单、属性状态，并为未来明文程序中的字符串/处理器定位提供锚点。现有公开XML里没有明确的LUT、VLT或View Assist控制项，因此没有找到“通过网络设一个LUT录制开关”这个捷径。allmenu不必然覆盖机内全部设置。

### 下一步

1. 相机与电脑进入可通信的Wi-Fi遥控连接，用户自行完成正常配对，不更改固件。
2. 仅获取 `getstate`、`getinfo capability`、`getinfo allmenu`、`getinfo curmenu` 四类响应。
3. 比较相同拍摄模式下V-Log/非V-Log，以及View Assist开/关时的响应。先确认接口是否暴露相关状态，不发未知设置值、不枚举未知命令。
4. 若无相关状态，下一层是被动捕获官方应用在用户正常操作时的流量，查看有无额外属性；不能保证官方应用支持操控机内View Assist。

已准备 [只读查询采集器](../collect_s5_readonly.py)，仅允许显式私网IPv4地址，四条预设GET，不自动认证、不申请控制、不切换模式、不改设置、不启流、不重试、不跟随重定向。发生相机错误即停止。已用mock离线测试通过，未向相机运行。

注意“GET”不保证相机端绝无会话或日志副作用；来源项目记录普通遥控操作曾导致busy/critical，不应运行其完整Connect/测试脚本代替只读采集。

## 2. 本地强线索：ipu_data 已知明文候选

在两版本的 `ipu_data`：

- 文件偏移：75,492,864（0x047FEE00）。
- 长度：262,144（256KiB）。
- 目录SHA-256：`8a39d2abd3999ab73c34db2476849cddf303ce389b35826850f9a700589b4a90`。
- 它精确等于256KiB全零数据的SHA-256。
- 该区flags=3，包内不是全零；两版附加16字节字段和数据均不同。

这比“看起来像密文”更有用：如果flags3沿用目录对解码后数据做SHA-256的语义，则有一个完整的全零明文测试向量。该假设还需升级器/解密实现验证，不能把摘要巧合或字段语义前提忽略。

已保存 [两版验证向量](known_plaintext_vectors.json)、[已知明文与字段探测结果](entrypoint_probe.json)。若保护方式是异或密钥流，则该区密文就是这一分区的密钥流；不代表能得到AES密钥，也不代表能解其他分区。

进一步检测：

- 两版全部flags3区的aux16没有重复。
- 从该区0/16/256/4096偏移取得的16字节块，在其他受保护载荷中没有找到复用匹配。
- 附加字段没有匹配密文CRC32/Adler32的各4字节位置（零长storage的零值匹配排除为无信息结果）。
- 受保护载荷里未发现32字节连续00/FF，未找出明显未保护的填充子块。

**价值：** 未来获得算法/参数时可以立即证伪或验证，避免“解出一串看似指令就声称成功”。当前没有因此破密。

## 3. USB/PTP维护信息候选：0x9703

[libgphoto2 ptp.h](https://raw.githubusercontent.com/gphoto/libgphoto2/master/camlibs/ptp2/ptp.h)中的确切定义：

`PTP_OC_PANASONIC_9703 0x9703 /* Mnt_GetInfo_GetVersion ... 1 arg? */`

这是具体的维护/版本信息候选，比泛泛猜调试命令更有依据。但注释带问号，没有原代S5支持记录或确切参数，**当前不应发送猜测参数**。

相关定义：

- 0x9102 = OpenSession，不是已经证实的ReadMemory。
- 0x9104 = get ext device id，参数仍不明确。
- 0x9110 = Get_Object infos。
- 0x9112 = Get Partial Object，4参数；对象偏移不是CPU地址。

正确验证顺序是先读取/捕获原代S5真实GetDeviceInfo的OperationsSupported和型号信息，再检查官方程序的现有请求。libgphoto2对GH5/G9的主机端补操作列表，不能当作S5实机广告能力。[相关主机逻辑](https://raw.githubusercontent.com/gphoto/libgphoto2/master/camlibs/ptp2/library.c)还可能设置SessionInitiatorInfo，故高层查询也不能不经审查就视为严格只读。

0x9406/0x9606/0x9607涉及格式化、清洁、设置或固件更新，0x9704涉及USB模式；不在只读检查范围。

## 4. 安全补丁差分：2.8→2.9

[官方更新说明](https://av.jpn.support.panasonic.com/support/global/cs/dsc/download/ff/dl/s5.html)对2.9明确写“Enhanced the security of products”。这说明现有两版本是有价值的安全变更样本，但没有披露漏洞类型或入口。

已定位9个目录摘要变化区，最小是128KiB的eep_fix；其他包括program、postboot1/3/5、osdover、zimage、rootfs1/2。名称不能直接确定模块职责，尤其eep_fix不必然是安全补丁所在。

**下一步：** 得到任一版本的明文或运行时片段后，按分区对齐做差分；现在直接密文diff不能定位补丁。邻近S5D官方包可作为封装/参数复用对照，但不能预设同密钥，更不能刷到S5。

## 5. BLE常量：将来定位协议处理器的锚点

[原代S5 BLE项目记录](https://raw.githubusercontent.com/tobiasbrummer/lux-lat-long-log/main/PROTOCOL.md)报告官方LUMIX Sync抓包及实机GPS/EXIF验证，提供：

- `MEI0`会话标记。
- Session UUID：`8d08a420-3213-11e6-8aca-0002a5d5c51b`。
- GPS UUID：`daff1bc0-3216-11e6-91c8-0002a5d5c51b`。

可以作为明文/内存中的字符串或16字节UUID搜索锚点；不是固件密钥或任意读写能力。其他项目的BLE唤醒记录存在配对要求，不能从GPS初始化推断所有BLE功能无认证。

## 实际优先级

1. **现在即可推进：** 用户机身的Wi-Fi菜单/状态证据，与已下载公开XML对比。
2. **固件研究验证点：** 保存ipu_data已知明文候选，配合新发现算法/升级器资料验证。
3. **需要设备/官方抓包证据：** USB DeviceInfo及维护信息0x9703的真实支持与参数。
4. **得到明文后推进：** 2.8/2.9安全差分、VLT加载与编码路径。

本轮没有得到可信UART针脚、服务手册、确定SoC型号或能执行自定义代码的入口。不能承诺Wi-Fi菜单或PTP维护信息会最终通向实时LUT烧录。
