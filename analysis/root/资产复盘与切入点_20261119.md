- `firmware_table.json`：已确认 `program`、`postboot1..5`、`music`、`zimage`、`rootfs1/2` 等偏移和大小。

- `rootfs1_dump.bin`、`rootfs2_dump.bin`：Linux 文件系统，包含通用加密库和启动用户空间，但没有找到 S5 专用更新密钥。

- `dtb_120800.bin`、`dtb_22ff000.bin`：GIC、定时器、UART、SDIO 和 USB 节点，未见 NAND/crypto 节点。

### 真机接口与工具

- Service USB `VID_04DA&PID_2370`：`0x5c` 读内存、`0x9c` 半字写入，已验证 RAM 读写和冷函数 detour。

## 入口结论

### 优先级一：引导阶段 UART 观测

低地址 DTB/bootargs 明确包含 `console=ttyAMA,115200`，UART 是当前最短的 postboot 入口。它能直接回答验签发生在哪个阶段、是否存在 Stubby/CM0、postboot 分区是否解密加载，以及失败原因。需要拆机接 UART，属于硬件操作。

### 优先级二：早期启动瞬时捕获

Service USB 只能看到升级完成后的常驻 RAM。postboot 可能在引导阶段执行后释放。可从 `0x80000000` Reset 向量、异常向量和固定加载地址继续做静态 CFG，寻找复制、解密、跳转和清理动作，再选择最早的常驻低地址冷函数做 RAM 捕获。当前没有证据支持再次钩主核 ECDSA 或 `0x87F4D32E`。

### 优先级三：容器前置解析

自定义包在主核 ECDSA 前就约 25 秒退出。应比较 `0x1c/0x1e`、目录版本副本、组件长度、明文摘要和外层认证块的消费顺序，定位前置拒绝。现有严格头包证明单改版本字不足以进入机身验签。

### 优先级四：恢复模式或 BootROM 入口

历史资产记录了 `SD.DAT`、恢复模式、UART 和 BootROM 入口研究。公开资料无法证明 MC801 量产机带可用 SD 引导，不能继续假设 Stubby 源码适配 S5。若 UART 显示存在恢复命令，再针对该入口做只读探测。

## 已证伪或不应重复

- 主核被动借 `0x87F4D152` NAND 对象：官方镜头/机身更新未命中。
- 主核 ECDSA 恒真：探针计数为 0，机身验签入口未进入。
- 静态 AES 调度表和高内存密钥扫描：完整扫描无有效机身密钥候选。
- 直接改 music：同版本包在版本比较阶段退出，且 music 仍是加密封装。
- 从当前 Service USB 常驻 RAM 直接读取 postboot：官方升级后没有保留 postboot 明文。
- 拔电池、热点函数和全零 BSS 代码洞：会清除或破坏实验状态。

## 推荐切入顺序

1. 先做 UART bootlog，一次性确认 postboot/BootROM 是否可见。
2. 无 UART 时，继续低地址 Reset→加载→跳转 CFG，定位最早可持久化捕获点。
3. 只有在确认前置解析已通过后，才重新构造带完整目录/认证一致性的测试包。
4. 不再重复刷同一官方包或同一版本降级实验。
