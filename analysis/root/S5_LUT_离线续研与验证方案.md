## 1. 根因假设清单

| 编号 | 假设 | 所需支持证据 | 如何证伪/区分 |
|---|---|---|---|
| H1 | 存在编码前LUT节点，但record模式策略门绕过它 | 同一个合规帧描述符可到LUT节点及编码器；找到按mode/state选择的有向分支 | 发现节点仅支持显示尺寸/格式，或编码器完全独立取帧，则不能仅NOP实现 |
| H2 | LUT只在显示/HDMI专用支路，编码链没有可接入节点 | 独立的队列、硬件通道、分辨率/色彩格式和DMA路由 | 若已有原生编码前可配置LUT节点则降低此假设；不能凭公开菜单缺失判硬件不支持 |
| H3 | 多种LUT缓存或状态：监看、回放、HDMI选择不同 | 不同cache handle/generation/用途标志的读者和生命周期 | 同一cache不等于同一图像输出节点；仍需确认像素生产者/消费者 |
| H4 | 所谓LUT字段只是保存/上位机状态或与PhotoStyle共变 | 配置字段解析→运行状态的真实映射，重复开关与无操作对照 | 仅序列化/UI更新、无图像处理读者，不足以支持录像关联 |
| H5 | 录像关联仅为曝光、V-Log模式、显示刷新等间接条件 | 固定其他变量后追配置字段到录像入口的真实数据/控制依赖 | 若录像只读PhotoStyle而非LUT表/变换结果，应否定“读LUT缓存”假设 |

以上均为候选，不赋予虚假的概率或已确认根因标签。

## 3. 每个候选点的逆向核查步骤

### O1：配置记录锚点

1. 交付同版本A(off)/B(on)/A2/B2配置及SHA-256；记录字段ID、record类型、数据内偏移和值。文件绝对偏移与record数据偏移分开。
2. 要求PhotoStyle、录像格式、分辨率、HDMI模式、拍摄/回放状态等保持一致；做无操作重复导出，剔除时间戳、序号及动态状态噪声。
3. 根据实际可用状态建立矩阵：预览/录像/回放 × LUT监看开关 × PhotoStyle。被机身禁用的组合标不可用，不强制解锁。HDMI监看开关另作独立变量。
4. 在S5明文代码中找记录分派器、键表/属性ID查找、getter/setter及其上游，而非只搜索某个小整数的立即数（低位ID误命中很多）。
5. 输出 `record → property dispatcher → runtime state → read sites`。这里只确认谁读取状态，不假设读取者已消费LUT像素或表。

**当前缺口：** 原始字段与配置对、S5程序明文。没有它们不能完成xref。

### O2：监看/录像/回放模式门

1. 以O1真实读者为起点标记CFG、调用者和状态来源。
2. 通过模式枚举的定义/写入点证明哪一个值对应录像、回放、预览；不能猜枚举0/1/2。
3. 区分“更新显示UI”“选择LUT表”“执行图像变换”“向编码器提交帧”四类调用。
4. 证明分支是策略选择，而不是资源存在、缓冲边界、色彩兼容、锁/错误处理或设备能力检查。
5. 做控制依赖和数据流：通过该分支之后实际编码输入是否变化；相同回调名、共享配置或模式关联都不足够。

**条件性patch逻辑（仅设计，不输出字节）：** 若已证明编码前已有兼容LUT路径，只重定向策略选择到该现有路径；保留所有能力、分辨率、格式、生命周期与错误检查。不能把若干条件统统NOP。

**当前缺口：** 明文基本块、原指令、ISA/Thumb状态及运行映射，故不存在可用分支点位。

### O3：LUT缓存与帧消费者

1. 从VLT载入器识别CPU表、硬件上传表、句柄、generation及缓冲分配/释放，不把文件RGB表地址当帧地址。
2. 跟踪哪个处理节点读表，以及变换后的图像落入哪个缓冲；CPU虚拟、物理、总线/DMA地址分别标明。
3. 明确帧格式、位深、色彩空间/范围、平面排列、尺寸、stride、时间戳、fence、引用计数和队列所有者。
4. 找编码器输入提交者，证明其读的是LUT后图像，而不是同帧未经处理的另一支路。
5. 若未来可做执行观测，先记录数值元数据（句柄/generation/frame_id/state），不复制全帧，不改返回值，不改资源所有权。

**hook限制：** 必须保全ABI、寄存器/标志、栈对齐、指令原子性、重入与缓存同步；日志写入预分配有限队列，满即丢日志不阻塞图像线程。这些是准入要求，不是本轮已经编写的相机hook。

### P1：编码前选择器（最后才考虑）

1. O2/O3证明完整生产者→变换→消费者关系，且节点支持所需内录格式/分辨率/帧率。
2. 排除已套两次LUT、V-Log/Rec.709范围误判和显示缩放帧误接编码器。
3. 优先调用现有合规路径，不修改编码核心、不替换任意显示指针。
4. 若必须新增帧拷贝、格式转换或硬件节点，停止“NOP/跳转即可”方案，重新评估吞吐、同步和硬件资源；不能靠移除保护条件硬接。
5. 没有可验证的只驻RAM加载/撤销通道时不进入实机patch。若必须涉及flash、校准、OTP、验证绕过或持久加载，本任务不生成该补丁。

### G1：同源比对必须从原始代码开始

1. 固定G100原镜像/导出模块的hash及正确分区基址，确认架构和ARM/Thumb解码。
2. 复核二手调用链的边/参数/头字段/数据流。升级路径与Wi-Fi WPA的AES调用分开。
3. 取得S5明文后，用CFG、调用邻域、常量引用、结构体字段和错误路径做匹配；改变版本/编译器的同源函数可能重排或内联。
4. 针对候选函数分别证明输入参数和副作用一致，再建立每版本地址映射。不采用G100与S5“同位置函数逻辑相同”的捷径。
5. 升级调用链只能帮助恢复载荷，不自动定位LUT编码链；两项验收分开。

## 4. 相机内部逻辑与上位机控制的分离

待交付原始Tether成功会话、客户端失败会话、客户端源码/可执行版本及SHA、USB模式、端点和时间线。

离线核查顺序：

1. 从PCAP/USBPcap提取URB和各方向端点，按传输实际语义重组；不要把USBPcap文件直接当PTP容器流，也不要将PTP/IP当USB PTP。
2. 检查container length/type/opcode/transaction id/参数数目、数据方向、同TID响应、完整长度、状态码与会话生命周期；transport STALL、超时、拒绝和语义无效分开。
3. 对齐官方成功与候选客户端失败的同一意图事务，确认接口/模式/会话/帧/分块差别；客户端构造错误先修，不能据此判断相机内部无功能。
4. 即便响应0x2001，也只能证明事务成功，不能证明状态已传到图像处理，更不能证明编码视频已套LUT。
5. 若上位机仅改变状态：追“协议解码→属性分派→内部状态→O2/O3”，而非把Tether函数地址当相机函数地址。
6. 若LUT仅在主机JPEG处理，则归外部显示路径，不算内录。

当前无原始会话，所以本轮不能排除全部客户端假阴性，也没有进行相机操作。

## 5. 最小离线POC：已实现部分与待实现部分

### 5.1 已实现并合成测试通过

工具：[lut_offline_evidence.py](../lut_offline_evidence.py)。只有文件读取、标准库解析及终端输出，无socket、USB、下载、刷机、固件写入或进程执行能力。

- `config-diff`：窄范围支持已记录的S5 0x9421 tag=0x080000a2布局。校验外/内长度、记录边界和终结符；按record id/type/出现次序对齐，结构变更拒绝猜测。列A/B或ABAB数据、位差和偏移。ABAB稳定只标状态相关，不称LUT字段或因果关系。
- `ptp-summary`：只解析用户已提取的单方向连续USB PTP容器流，校验长度/类型/参数并列TID。不是PCAP解码器，不做跨方向事务/会话或LUT语义推断。

- `self-test`：合成配置ABAB和不稳定对照、坏长度/记录/标记拒绝、PTP长度/方向检查。**不模拟S5、不证明CPU解码、hook安全或LUT录像有效。**

### 阶段B：未来可选实机观测，不是当前可上机补丁

B3. 证明真实encoder consumer与LUT节点关系后，才允许设计一个有功能开关、RAM暂存的最小策略变更。运行时跳转写入需停在已证明安全点且处理I/D cache/多核同步，不做任意热写。

B4. 最终验收是从SD卡直接复制原始视频，在关闭播放器/剪辑软件LUT和自动色彩变换后，像素/色彩测试符合预期；屏幕、回放显示或HDMI效果不作为内录证据。

**本轮没有满足阶段B门槛的地址或加载通道，所以不存在当前可直接上机运行的hook/patch。验证顺序可直接采用，但不能宣称已准备好机身补丁。**

## 7. 失败回退方案

| 阶段 | 失败处理 |
|---|---|
| 离线解析 | 保留原文件及SHA；schema/长度不符即拒绝，不自动修复或写回配置 |
| 同源/地址验证 | 丢弃匹配假设，不生成补丁；不同版本分别确认，禁止偏移平移 |
| 逻辑仿真 | 恢复未修改模型，记录破坏的不变量；不能以NOP错误路径“修好”测试 |
| 未来观测hook | 只用预先验证的撤销路径恢复原RAM字节/控制流和cache状态；若暂存hook只能靠重启撤销，须先证明该加载机制不持久化，否则不测试 |
| 未来功能补丁 | 单一开关回到原路由，等待在途帧/fence完成后安全卸载；避免存储写入中强制断电。若无法保证恢复原路由或原RAM，禁止加载 |
| 不明更新/EEPROM/flash副作用 | 停止；不自动刷回、不恢复别人机身备份、不声称拔电池必能恢复 |

重启不能保证撤销持久设置、flash或校准改变；本任务不生成这些变更。所谓只读hook也不能保证不会导致崩溃或丢失尚未落盘视频。
