# 低地址 Reset→加载→跳转 CFG（2026-11-19）

## 已确认的执行链

转储 `lowmem_0_2M.bin` 对应物理地址 `0x80000000`。异常向量和 Reset 入口是 ARM 状态。

```text
0x80000000  Reset vector
    ↓
0x80000050  关 IRQ/FIQ，关闭 MMU/cache，SP=0x13000，读取 MPIDR
    ├─ 非主核 → 0x80000240，等待 mailbox/事件
    └─ 主核 → 0x80000090，等待硬件状态
             ↓
0x80000108  cache/TLB 初始化
0x80000134  清零范围 [literal 0xD044, literal 0xE144)
0x80000174  从 literal 0x9868 复制到 0xD000 附近
0x8000019C  BLX 0x800010E8，进入 Thumb
             └─ 0x800010E8 处理片内表/寄存器，不是 AES/签名代码
0x800001E4  GPIO/时钟/外设初始化
0x800001E8  BLX 0x80001CF4，进入 Thumb
             └─ 0x80001CF4 初始化 0x60000 区域和事件结构
0x800001EC  BLX 0x80001E64，进入 Thumb
             └─ 低层时钟/事件等待与寄存器设置
0x8000023C  LDR PC，[literal 0x8000048C] → 0x330
0x800003B8  低层 cache/同步处理
0x800003C4  LDR PC，[literal 0x800004A4] → 0x06280004
             = 服务别名 0x86280004，主核 program 入口
```

异常向量 `0x8000004C` 的 literal `0x80000448` 为 `0x06280000`，同样指向主核 program 映射区。`0x800003C4` 是当前低地址启动链中最明确的主核交接点。

## 最早可持久化捕获点

### 首选 `0x800003C4`

- 指令是 ARM `ldr pc, [pc, #0xd8]`，原始字节位于常驻低地址启动代码。
- 目标 literal 明确为 `0x06280004`，可在跳转前保存寄存器、目标值和启动状态。
- 该点位于所有低地址初始化之后、主核 program 交接之前，适合判断是否实际走到主核加载阶段。
- 捕获区应放在启动代码不会清零的低地址保留区，并附带 magic、计数器和版本字段。

### 次选 `0x8000019C`

- 这是第一次进入 Thumb 初始化函数前的冷调用点。
- 适合确认主核是否完成清零、复制和 MMIO 初始化。
- 过早写入高地址 RAM 可能尚未映射，不能直接复用主核 `0x8708xxxx` rodata 洞。

### 不建议当前钩取的点

- `0x800010E8`、`0x80001CF4`、`0x80001E64` 属于早期硬件/事件初始化，调用时机和 cache/MMU 状态敏感。
- `0x8000023C` 的 `0x330` 目标属于启动辅助路径，静态快照没有证明它是 postboot 入口。

## 关键排除

- 低地址启动代码未发现 `UPD\0`、`FW_UPDATE_MODE`、NAND、Panasonic 更新日志或 AES/ECDSA 实现。
- 低地址代码只负责处理器启动、缓存/MMU、GPIO/时钟、事件结构和主核 program 交接。
- 因此 postboot 最早入口不在已转储的 `0x80000000–0x80002000` 启动桩内。它更可能在 BootROM/隐藏引导阶段，或由主核 program 交接后的未公开加载路径进入。

## 下一步实验设计

1. 只在 `0x800003C4` 建立 ARM 状态计数探针，保存 magic、MPIDR、SP、literal 目标和计数器。
2. 捕获区使用低地址启动代码明确未使用的保留区，先做静态范围检查，避开清零/复制目标。
3. 热重启后读取捕获区，确认探针是否跨越启动阶段存活。
4. 若 `0x800003C4` 命中，再扩展为保存主核交接前的少量内存窗口。不要在该阶段调用 NAND 或 AES。

## 首次真机捕获结果

`0x800003C4` 的 ARM 探针已在热重启后命中一次，记录为：

- magic `0x52545354`
- `r0=0x800`、`r1=0x00C5187D`、`r2=0x3`、`r3=0xFFFFFFFF`
- 目标 `0x06280004`
- 计数器 `1`

这证明低地址 Reset 链确实执行到主核 program 交接点。`0x00C51800` 附近可由 Service USB 读取，且包含 ARM 代码，但该区域扫描到 `/etc/localtime`、`mtkbt`、`SDAP_DEVDB` 等 Bluetooth/系统服务痕迹，没有 `UPD`、`FW_UPDATE`、NAND、AES 或 ECDSA 明文标识。当前更像另一个常驻系统/协处理器映射区，不应直接命名为 postboot。

## 增强捕获结果

增强探针再次命中一次，记录为：

- `SP=0x00013000`，与 Reset 初始化的启动栈一致
- `LR=0x000003C4`，对应 `0x800003C0` 调用返回到交接指令
- `CPSR=0x600001D3`，处于 SVC 模式，IRQ/FIQ 关闭
- 原始 `r1=0x00C5187D`，对齐窗口基址 `0x00C5187C`
- 窗口内容按 ARM 解码为普通 C 风格函数片段，包含 `BL 0x00C53024`、`BL 0x00B126C4` 和栈帧访问

该窗口没有更新、解密或签名语义。结合 C5 区域中的 `mtkbt`、`/etc/localtime` 和 `SDAP_DEVDB` 字符串，`r1` 更像启动时残留的系统/协处理器指针或带标记指针，当前不能判定为 postboot 入口。探针已记录了最早交接时刻和 CPU 状态，后续应转向 `0x06280004` 之后的主核早期入口或 UART/BootROM 观测。
