# 动态追踪：钩子安装与安全规程

> 目的：在相机上记录某个函数被调用时的实参，用于逆向那些"静态找不到引用"的 API
> （例如 `GOT_File_Open`、`CFS_Open`）。

## 1. 原理

```
原函数入口:  <前 8 字节>
改成:        ldr.w pc, [pc, #0]      ; 远跳，不破坏 lr
             .word 0x86370001        ; 我们的 logger（Thumb）
logger:      push {r4-r7}            ; 保存要用的寄存器
             mov r4,r0 ... 记录实参到 0x8F302100
             pop {r4-r7}
             <原前 8 字节>           ; 补执行被打断的指令
             ldr.w pc, [pc, #0]
             .word <返回地址|1>      ; 回到原函数 hook+8
```

计数器在 `0x8F302000`，每条记录 16 字节（r0~r3），最多 64 条。

**4 字节槽位**（如系统调用桩）用 `b.w` 直接跳（要求 ±16 MiB 内），此时 logger
不需要补执行原指令。

## 2. 工具

```bash
python tools/trace_hook.py install 0x8647994C 0x86479954 --size 8
python tools/trace_hook.py read
python tools/trace_hook.py clear
python tools/trace_hook.py restore 0x8647994C f0b591b00d460446
```

- 默认返回地址 = `hook + size`
- logger 会自动补执行被覆盖的原始字节
- ⚠️ 若被覆盖的指令是 PC 相对（`adr`/`ldr [pc]`/`b`），搬移后会算错地址，
  这种函数不能这样钩（要么选别的入口，要么手工处理）

## 3. 安全规程（血泪教训）

**2026-11-23 事故**：把日志 detour 装到**日志分发桩** `0x868E59A0`（热路径）上做自检，
相机随即失去响应（USB 仍枚举，但 bulk 传输超时），只能拔电池恢复。

**根因（已定位并修复）**：日志程序里用 `r0/r2/r3` 保存计数器地址，
但**返回前没有恢复被调函数的原始 `r0~r3`**。日志分发函数收到被污染的参数后崩溃。

修复：logger 在跳回之前必须执行

```asm
mov r0, r4
mov r1, r5
mov r2, r6
mov r3, r7
pop {r4-r7}
```

`tools/trace_hook.py` 已加入这段恢复代码（logger 从 68 字节变为 76 字节）。

**规程**：

1. **先在低频、可控的路径上验证工具**
   - 安全：对焦音包装 `0x8647994C`（半按快门触发）
   - 危险：日志分发 `0x868E59A0`、系统调用桩、按键处理、任何"每帧都跑"的函数
2. 安装后**先读回校验**（工具已内置），再触发
3. 触发前确认恢复命令和原始字节都已记录
4. 出问题拔电池（RAM 清空即恢复原厂），**不要只按电源键**——补丁会跨重启保留
5. 每次只改一个地方，改完立即验证
