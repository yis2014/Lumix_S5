# 夜间工作交接（2026-11-23 凌晨）

> 相机目前处于服务模式、状态干净（所有挂钩点已回原厂）。
> 本文档汇总夜间新增的发现和早上的行动建议。

## 1. 夜间新增：SD 驱动层（重要）

绕开文件系统直接读 SD 扇区的路径：

| 函数 | 日志串地址 | 函数入口 | 调用者 |
|---|---|---|---|
| `SDD_Open` | 0x863C06F4 | **0x863C0312** | 0x863BDF38、0x863CA300 |
| `SDD_Read` | 0x863C0758 | **0x863C0504** | 0x863BE130、0x863CA4FC |
| `SDD_Write` | 0x863C0DA8 | 待定位 | — |
| `SDD_Ioctl` | 0x863C007C | 待定位 | — |

`SDD_Read` 的寄存器形态：

```asm
863c0504  push.w {r0-r8,sb,sl,fp,ip,lr}
          r6 = r0        ; 上下文指针（[r6] 必须非空，[r6+4] 与 2 比较）
          sl = r1        ; 指向扇区号的指针（ldr r1,[sl]）
          r7 = r2        ; 目的缓冲区
          sb = r3        ; 扇区数量
```

上层包装（先确保 SD 打开，再转发给 SDD_Read）：

```asm
863ca4c0  ; 参数 (r0,r1,r2,r3)；先检查 global+0x28 == 1
          ; 再 bl 0x863CA2D6（确保打开），最后 bl SDD_Read
```

## 2. SD 子系统当前状态（实机只读侦察）

```
0x88AB0774+0x28 = 0x00000001    ← "已打开"状态，检查会通过
0x88AB0774+0x30 = 0x08AF57C8    ← 指向 SD 卡信息结构
```

`0x88AF57C8` 里是 SD 卡的 **CID/CSD 寄存器数据**：

```
+0x00: 210100C1 039FC000 039D4000 00000200   ; 0x200 = 512 扇区大小
+0x30: 0A00C1FF AE55DA01 32472526 4D534133   ; "3ASM" 卡序列号标记
```

结论：**SD 卡已被相机正常初始化**，硬件通路是通的。

## 3. 卡住的地方

`SDD_Read` 需要的上下文指针（r0）不是上面那个卡信息结构；
而它的上层包装 `0x863CA4C0` 没有任何可搜索的引用（没有 BL/BLX、没有字面量指针），
说明是运行时构建的调用表。

**没有用户在场时，用猜测的上下文调用 `SDD_Read` 风险过高**（一旦崩，只能拔电池），
所以夜间没有做这个实验。

## 4. 早上的建议行动（按顺序）

   验证修复后的追踪工具（这次不会卡死）

### B. 追踪 SD 读取的上下文（30 分钟，低风险）

把追踪钩子装在 **`0x863CA4C0`（读包装）** 上，正常模式拍一张照片：

```bash
python tools/trace_hook.py install 0x863CA4C0 0x863CA4C8 --size 8
# 正常模式拍照 → 回服务模式
python tools/trace_hook.py read
```

期望：记录到 r0（上下文指针）、r1（扇区号指针）、r2（缓冲）、r3（数量）。

拿到真实的 r0 后，就能在 payload 里**原样复用**它调用 SDD_Read。

### C. 安全验证 SD 上下文（推荐先做）

用只读的 `SDD_Ioctl(cmd=0x08)` 查扇区大小——它只把 `[card+0xC]` 写到输出指针，不改卡状态：

```bash
python tools/load_program.py push payloads/ioctl_probe.bin
# 半按快门
# 读 0x8F300080
```

期望：

```
+0  0xC1C1C1C1  进入
+4  返回值
+8  0x00000200  扇区大小（关键！）
+12 0xC2C2C2C2  正常返回
```

- 看到 `0x200` → **上下文和调用约定完全正确**，SDD_Read 大概率也能用
- 看到 `C1C1C1C1` 但没 `C2C2C2C2` → 调用挂住，拔电池
- 死机 → 拔电池

### D. 调用 SDD_Read 探测（有风险）



工具链已装好（`tools/armgcc`，ARM GCC 15.2.1），payload 用 C 写：

```powershell
# 编译（若 pwsh 不可用，用同样参数手工调用 gcc/objcopy）
# 产物：payloads\sd_probe.bin（92 字节）
```

探测程序 `payloads/sd_probe.c` 会：

```
r0 = 0x08AB07A4   SD 上下文（已验证符合 SDD_Read 的检查）
r1 = 0x0F303000   偏移指针（指向 0）
r2 = 0x0F304000   读缓冲
r3 = 0x200        512
blx 0x863C0505    SDD_Read
```

结果写到 `0x8F300020`：

```
+0  0xA1A1A1A1  = 进入
+4  返回值
+8  读到的第一个字（扇区 0 应为 0x00000000 或 MBR 签名相关）
+12 0xA2A2A2A2  = 正常返回
```

操作：

```bash
python tools/load_program.py push payloads/sd_probe.bin
# 半按快门
# 读 0x8F300020
```

**判读**：
- 看到 `A2A2A2A2` → 调用成功，返回值和数据都有意义
- 只有 `A1A1A1A1` 没有 `A2A2A2A2` → 调用挂住（拔电池恢复），参数不对
- 相机死机 → 拔电池，记录现象

### E. FAT 读取并执行（已写好，待验证）

`payloads/fat_load.bin`（1027 字节）读 SD 卡上的 `LUMIX.BIN`（8.3 名 `LUMIX   BIN`），
加载到 `0x86360000` 后**直接跳转执行**。

```bash
python tools/load_program.py push payloads/fat_load.bin
# 半按快门 → loader 读卡 → 跳转到程序
```

标记在 `0x8F300040`：

| 偏移 | 值 | 含义 |
|---|---|---|
| +0 | 0xB1B1 | 开始 |
| +0 | 0xB2B2 | 引导扇区解析完成 |
| +1 | 0xE001 | 读扇区 0 失败 |
| +1 | 0xE002 | 找不到 FAT32 分区 |
| +1 | 0xE003 | BPB 解析失败 |
| +1 | 0xE004 | 根目录里没有 LUMIX.BIN |
| +1 | 0xE005 | 文件为空或 > 60 KiB |
| +1 | 0xE006 | 读簇失败 |
| +1 | 0xB0B0 | 文件已加载并跳转 |
| +2 | — | 文件大小 |
| +3 | — | 首簇号 |

**限制**：文件必须 < 60 KiB（loader 自己占用 `0x86370000` 起的空间）。
