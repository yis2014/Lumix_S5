# 醒来后的 5 分钟验证计划

> 相机现在处于服务模式且状态干净（日志桩、GOT 钩子、对焦钩子都回原厂）。
> 以下命令按顺序执行即可，不需要再重新逆向。

## 0. 先确认相机在线

```bash
python tools/payload_test.py check
```

## 1. 验证「注入执行」仍然有效（30 秒）

```bash
python tools/load_program.py push out/prog_counter.bin
```

然后**半按一次快门**，再：

```bash
python tools/payload_test.py check   # 或读 0x8F300000 应为 0,1,2,3...
```

期望：`0x8F300000` 出现 `0x00000000 0x00000001 0x00000002 ...`（上次已实测通过）。

## 2. 验证修好的追踪工具（1 分钟，这条最重要）

上次相机卡死是因为 logger 没恢复 `r0~r3`，已修复（提交 `c12f65b`）。

```bash
python tools/trace_hook.py install 0x8647994C 0x86479954 --size 8
```

**半按一次快门**（这次对焦音不会响，是预期），然后：

```bash
python tools/trace_hook.py read
```

期望：`count >= 1`，`entries[0]` 的 `r0` 是音效 id（对焦音应为 1 或类似小整数）。

- 若计数器动了 → 追踪工具验证通过，可以进入第 3 步
- 若计数器没动 → 说明挂钩点没被调用，换 `0x864783EA`（声音队列消费者）
- 若相机死机 → 拔电池，工具还有问题，需要再查

然后恢复：

```bash
python tools/trace_hook.py restore 0x8647994C f0b591b00d460446
```

## 3. 追踪 GOT_File_Open（5 分钟，这是方案 B 的关键）

```bash
python tools/log_hook.py install
```

然后**正常模式操作**（关机 → 正常开机 → 拍一张照片 / 录一段视频 → 关机 → 进服务模式），再：

```bash
python tools/log_hook.py read
```

期望：`count > 0`，能看到 `GOT_File_Open` 被调用时的 4 个实参。

**判读**：
- 若 `r0` 或 `r1` 落在 RAM 字符串区（0x8xxxxxxx）→ 它很可能就是"按路径打开文件"
- 全为 0 或奇怪值 → 不是文件打开，继续找别的入口
