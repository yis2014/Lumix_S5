# Lumix S5 固件容器格式（v2.9，从零逆出）

样本：`S5___V29.bin`，90,238,464 字节 (0x560EE00)
来源：Panasonic 官方 zip `S5___V29.zip` (87,765,879 B, sha256 bfba5856…)
解包后 .bin sha256 = b2ec4aeec209693b874df8dfdf11fc85b38fa4675b44ec554b7a167f430827e1

## 总体布局

| 偏移 | 内容 |
|---|---|
| `0x000` | 外层头（0x200 字节，`UPD\0` + `MC801`） |
| `0x200` | 外层目录：1 条记录 `panasonic`（类型 0），0x5c 字节 + 补齐 |
| `0x2A0` | 内层容器头（0x4C 字节，同样是 `UPD\0` + `MC801`） |
| `0x2EC` | 内层目录：48 条记录 × 0x5C = 0x1140 |
| `0x142C` | 零填充到 0x1600 |
| `0x1600` | 数据区：48 个 blob 按目录顺序首尾相接 |
| … | 数据区长度 = Σ(每条的 size) = 0x560D800 |

关键恒等式（全部实测成立）：

```
file_size        = 0x200 + Σ size
data_start       = 0x1600
blob_i 的偏移     = 0x200 + addr_i          # addr 从 0x1400 起连续
Σ size           = 0x560D800
0x200 + 0x560D800 = 0x560EE00 = EOF
```

## 记录结构（0x5C 字节）

```
+0x00  char  name[12]      ASCII，NUL 补齐（"postboot1"、"zimage"…）
+0x0C  u32   addr          镜像内偏移，从 0x1400 起连续递增
+0x10  u32   size          blob 长度；同时也是 flash 上的长度
+0x14  u32   flash_addr    写入 flash 的目标地址（有空洞/对齐）
+0x18  u32   flags         只有 2 和 3 两种
+0x1C  u8    sha256[32]    明文的 SHA-256
+0x3C  u8    iv[16]        flags=3 非零；flags=2 全零
+0x4C  u8    rsv[16]       全零
```

## flags 语义（已证实）

- `flags = 2`：数据区直接是**明文**。7 条这样的记录
  （storage / history / lens_hist / fileinfo / ninsho_db / wifi_info / menu_save）
  的 `sha256(blob) == 记录里的 sha256`，全部命中。
  它们的明文恰好全是 0x00（未使用的占位分区），但哈希关系已证明"摘要是对明文算的"。
- `flags = 3`：数据区是**密文**，长度与明文相同；`sha256(密文) != 记录里的 sha256`。
  每个 16 字节块在 0xA00000 规模的分区里都**没有任何重复块** → 不是 ECB，
  是 CBC/CTR/流式；16 字节 `iv` 字段很可能就是 IV/nonce。

## 外层头的两个未知量

```
+0x34  u32 0x00000200      目录偏移
+0x38  u32 0x0560EC00      载荷长度 = 0x1400 + 0x560D800
+0x3C  u32 0x8E73AAC0      未知（不是整文件 CRC32）
```
`panasonic` 记录 +0x20 处有 32 字节
`9acfa33f545b047520c25d2d5e0870bbc935ee0842c8d9cda44e058e5629bc7a`，
对整文件 / 0x200 起 / 0x2A0 起 / 数据区 / 表区 / 哈希拼接等候选都**不匹配**。
它要么是对"解密后整幅镜像"的 SHA-256，要么是 HMAC/签名类。这是整个方案的关键未知。

## 内层头（0x2A0）

与外层头逐字节相同，只有 `+0x40..+0x4B` 不同：

```
+0x40  u32 0x00001400      = 镜像加载地址（第一条记录的 addr）
+0x44  u32 0x0560D800      = 数据区总长
+0x48  u32 0x00000030      = 记录数 48
```
